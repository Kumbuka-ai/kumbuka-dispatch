# Where `assistant-surface.md` came from, and why it is here

`assistant-surface.md` is a **verbatim copy** of

    platform-specs @ 28317c8
    docs/concepts/concept-dispatch-assistant-surface-and-process-verbs.md

taken on 2026-09-18 for sub-sprint satellite/26.6.

## Why a copy and not a reference

The conformance probes take their expected values — the tool descriptions, the
refusal message patterns, the `next` table — from the contract, and never from
the service or from the service's own declaration. A probe that reads its
expectation out of the thing it is probing asserts that two copies agree, not
that either is right.

The contract lives in another repository. A test in this one cannot read it, so
it is copied here. That makes this file a second copy of a document, which is
the thing this project usually refuses — and the trade is deliberate, because
the alternative is worse in a specific way: the probe would have to hold its
expectations in Java, beside the declaration it checks, and the two would be
edited in the same commit by the same hand. A copy that is *stale* turns the
probe red and somebody looks; an expectation written next to the code it checks
is green forever and says nothing.

## What to do when the contract changes

Re-copy this file, run the probes, and fix what goes red. In that order — the
contract is the source, and a probe that is made to pass by editing this copy
has been made to pass by editing the specification.

## What must not be done

Do not edit this file to make a probe pass. If the service is right and the
contract is wrong, the contract is changed in `platform-specs` first and copied
here afterwards; that is a concept-apparatus act, not this one's.
